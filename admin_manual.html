관리자 이용 매뉴얼

설치가 끝난 뒤 실제 운영자가 수행하는 설정과 관리 절차를 화면 순서대로 설명합니다.

관리자최대 2계정
기관 계정기관당 최대 5개
전체 조회모든 기관·성과·실증
전체 관리기관/진행항목/실증/계정

1. 로그인 및 관리자 모드 전환

시스템 접속

index.html 또는 배포된 대표 URL로 접속합니다.

관리자 ID와 비밀번호 입력

설치 시 만든 관리자 계정 또는 다른 관리자가 발급한 관리자 계정을 사용합니다.

첫 로그인 비밀번호 변경

초기 비밀번호 계정은 로그인 직후 비밀번호 변경창이 표시됩니다. 8자 이상 새 비밀번호를 저장합니다.

관리자 모드 진입

기관 화면 상단의 관리자 버튼을 누릅니다. 관리자 모드에서 좌측 메뉴가 표시됩니다.

관리자 모드에서 다시 기관 화면을 누르면 실제 기관 사용자가 보는 화면을 점검할 수 있습니다.

2. 사용자 계정 관리

관리자 → 사용자 관리

2-1. 기관 계정 만들기

+ 계정 추가

사용자 관리 화면의 계정 추가 버튼을 누릅니다.

계정 유형과 기관 선택

기관 사용자를 선택하고 경복대학교, 돌봄과 미래, 에임랩, 정션메드 중 소속기관을 지정합니다.

사용자명·로그인 ID·초기 비밀번호 입력

로그인 ID는 중복되지 않게 지정합니다. 초기 비밀번호는 사용자에게 별도 전달합니다.

생성 후 사용자에게 전달

URL, 로그인 ID, 초기 비밀번호를 전달합니다. 사용자는 첫 로그인 후 비밀번호를 변경합니다.

기관별 활성 계정은 최대 5개입니다. 관리자 활성 계정은 최대 2개입니다.

2-2. 두 번째 관리자 만들기

+ 계정 추가 → 관리자를 선택하고 이름, 로그인 ID, 초기 비밀번호를 입력합니다. 장애·비밀번호 분실에 대비해 관리자 2계정 운영을 권장합니다.

2-3. 계정 중지·관리

사용자 목록에서 계정 상태를 확인합니다. 담당자가 변경되거나 더 이상 접속할 필요가 없으면 계정을 비활성화/삭제하고 새 담당자 계정을 발급합니다.

3. 비밀번호 변경 및 분실 처리

3-1. 본인 비밀번호 변경

상단 내 계정 선택

현재 로그인한 사용자 정보와 새 비밀번호 입력창을 엽니다.

새 비밀번호 2회 입력

새 비밀번호와 확인값을 동일하게 입력한 뒤 저장합니다.

3-2. 기관 사용자가 비밀번호를 잊은 경우

사용자가 로그인 화면에서 ‘비밀번호 초기화 요청’

로그인 ID를 입력해 초기화 요청을 등록합니다.

관리자 → 사용자 관리 확인

상단의 비밀번호 초기화 요청 목록에서 해당 사용자를 찾습니다.

비밀번호 재설정

새 임시 비밀번호를 입력해 재설정합니다. 기존 비밀번호는 조회되지 않습니다.

사용자에게 임시 비밀번호 전달

전화·메신저 등 별도 채널로 전달합니다. 사용자는 로그인 후 다시 본인 비밀번호로 변경합니다.

관리자 계정 하나만 있고 해당 관리자가 비밀번호를 잊으면 내부에서 복구할 관리자가 없습니다. 관리자 2계정을 유지하십시오.

4. 기관 관리

관리자 → 기관 관리

공식 참여기관의 표시명과 담당 정보를 관리합니다. 기관명을 변경할 때는 기존 진행항목·실증 책임기관과 연결 관계가 영향을 받을 수 있으므로 운영 중에는 불필요한 명칭 변경을 피합니다.

  • 정션메드: 주관기관
  • 경복대학교
  • 돌봄과 미래
  • 에임랩

5. 진행항목 관리

관리자 → 진행항목

5-1. 새 진행항목 추가

+ 진행항목 추가

새 항목을 만듭니다.

항목명·책임기관·협업기관 설정

실제 완료 책임이 있는 기관을 책임기관으로 지정합니다.

기준일정과 현재일정 구분

사업계획서 일정은 기준일정으로 보존하고 실제 운영 일정은 현재일정에 입력합니다. 일정이 변경되면 변경 사유를 기록합니다.

완료기준 입력

산출물, 제출자료, 정량 기준 등 완료 여부를 판단할 수 있는 문장으로 작성합니다.

고유번호 확인

고유번호를 비워 두면 AX-0001 형식으로 자동 생성됩니다. 관리자는 직접 수정하거나 표시번호를 제거할 수 있습니다.

5-2. 세부항목 만들기

큰 진행항목을 클릭해 세부항목을 추가합니다. 내부 DB ID는 고정되므로 표시 고유번호를 바꿔도 요청·협의 연결은 유지됩니다.

5-3. 비활성화

운영 중 제외된 항목은 삭제 대신 비활성화를 우선 사용합니다. 기존 기록과 연결관계를 보존할 수 있습니다.

6. 요청·회신 관리

관리자 → 요청·회신

6-1. 요청 등록

요청 제목, 내용, 수신기관(복수 선택 가능), 요청일, 회신 희망일, 관련 진행항목을 지정합니다.

6-2. 관련 진행항목 연결

관련 진행항목을 지정하면 요청 화면에 [AX-XXXX] 태그가 표시되고 클릭 시 해당 진행항목으로 이동합니다.

6-3. 수정·삭제 규칙

상태처리
회신 없음작성 기관은 자기 요청 수정·삭제 가능. 관리자는 전체 관리 가능.
회신 1건 이상원문 잠금. 일반 수정·삭제 불가.
기관별 회신각 기관은 자기 회신만 작성·수정. 관리자는 전체 회신 상태 확인.
회신이 달린 원문 잠금은 협업 기록을 사후 변경하지 않기 위한 운영 원칙입니다.

7. 협의사항 관리

관리자 → 협의사항

공식 요청보다 가벼운 협의, 확인내용, 결정 전 의견을 기록합니다. 관련 진행항목을 연결할 수 있으며 고유번호를 누르면 해당 항목으로 이동합니다.

원문에 답변이 달리면 원문이 잠깁니다. 후속 내용은 새 답변으로 이어서 기록합니다.

8. 실증 관리

관리자 → 실증 관리

8-1. 실증기관 등록

실증기관 추가

기관명을 입력합니다.

책임기관 지정

해당 실증기관 실적을 실제로 입력·관리할 참여기관을 지정합니다.

목표 인원 입력

해당 실증기관에서 완료해야 하는 목표 인원을 입력합니다.

관련 진행항목 연결

기존 진행항목 중 실증과 연결되는 항목을 복수 체크할 수 있습니다.

8-2. 단계별 완료 인원

단계진척도 비중입력값
사전설문25%완료 인원
교육25%완료 인원
사용25%완료 인원
사후설문25%완료 인원

예: 목표 40명, 사전 40명·교육 20명·사용 0명·사후 0명 → 전체 진척도 37.5%입니다.

8-3. 사례비

사례비 체크는 해당 실증기관 사례비 지급 완료 여부를 기록합니다. 진행률 계산에는 반영되지 않습니다. 화면에서 적색 체크로 구분됩니다.

8-4. 권한

관리자는 실증기관의 생성·수정·삭제, 책임기관 변경, 목표 인원 변경, 연계 진행항목 변경이 가능합니다. 책임기관 사용자는 자기 책임 실증기관의 단계별 완료 인원과 사례비 상태만 수정합니다. 타 기관은 조회만 합니다.

9. 성과목표·전체 일정·회의·문서

성과목표

사업계획서의 정량·정성 성과지표를 조회하고 현재값과 진행상태를 관리합니다. 실제 실적이 확인된 시점에 값을 갱신합니다.

전체 일정

진행항목의 현재 시작일·종료일을 기반으로 일정 흐름을 확인합니다. 기준일정은 사업계획서 원안 비교용으로 보존합니다.

회의·문서

회의 일정과 공유문서를 확인합니다. 회의에서 결정된 실행사항은 별도 진행항목으로 생성해 책임기관과 기한을 명확히 하는 방식으로 운영합니다.

10. 데이터 백업·복원

관리자 → 관리설정

JSON 내보내기

JSON 내보내기를 눌러 현재 사업 상태를 파일로 저장합니다. 중요한 변경 전, 월 1회 이상, 최종보고 전 백업을 권장합니다.

JSON 불러오기

기존 백업파일을 선택해 복원합니다. 잘못된 파일을 선택하면 오류가 표시됩니다.

초기 데이터로 복원

초기 데이터 복원은 운영 중 입력한 수정내용을 되돌릴 수 있습니다. 반드시 JSON 백업 후 사용하십시오.

11. 보안 운영 원칙

  • 관리자 계정 2개를 유지하고 서로 다른 담당자가 보관
  • 기관 계정은 담당자별 개별 발급, 공용 비밀번호 사용 최소화
  • 퇴사·담당변경 시 즉시 비활성화 또는 삭제
  • Secret/Service Role Key는 HTML·JavaScript·GitHub에 저장 금지
  • 웹서비스는 HTTPS 사용
  • 상담 원문, 주민등록번호, 음성·생체정보 등 민감 원본정보는 이 시스템에 입력 금지
  • 요청·협의 원문은 답변 이후 잠금 유지

12. 자주 발생하는 문제

증상확인사항
로그인 실패ID 오타, 계정 비활성, 비밀번호 확인. 필요 시 초기화 요청 처리.
관리자 버튼이 없음현재 계정의 role이 admin인지 사용자 관리에서 확인.
기관 데이터 수정 버튼이 없음로그인 계정 소속기관과 해당 데이터 책임/작성기관이 일치하는지 확인.
요청 원문 수정이 안 됨회신이 하나라도 등록되면 정상적으로 잠금됨.
실증 완료 인원 저장 실패완료 인원이 목표 인원을 초과했는지 확인.
사례비 컬럼 오류신규 설치 SQL에 stipend_paid 컬럼이 포함되었는지 확인.
공유DB 연결 안 됨supabase-config.js의 URL/Publishable Key, Supabase 프로젝트 상태, RLS 및 Edge Function 상태 확인.
